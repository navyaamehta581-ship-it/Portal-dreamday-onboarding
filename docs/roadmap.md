# Activation Intelligence roadmap

Use the [six-step active blueprint](blueprint/activation-intelligence.md) and [current handoff](activation/handoff.md) when selecting work. The historical 516-atom backlog is retained for dependency/provenance reference, not the current delivery queue.

1. Review the provisional activation contract and UI/backend ownership together. Settle full runtime response validation and customer/developer/Chris view acceptance.
2. Obtain actual customer briefing/agreement and production principal authorization. Keep fictional intake and Portal records explicitly simulated.
3. Validate personalized next actions and blocker recovery with durable restart/conflict evidence against admitted real context.
4. Connect independently admitted technical artifacts/check receipts where authorized. Keep read-only GitHub observations distinct from execution and verification.
5. Evaluate customer outcomes against an agreed baseline. Report unknowns; do not infer deployment, adoption or ROI from tests.
6. Select a managed Portal/AiKA integration architecture only after tenant contracts, identity and runtime capabilities are verified, then review release/rollback evidence.

Reusable workflow, backend, LLM and conversation logic remains available. Do not rename core directories/contracts or replace Navyaa’s frontend as a branding cleanup. Each implementation PR needs scoped ownership, dependencies, acceptance and evidence. This roadmap marks no historical atom complete and authorizes no live external execution.
